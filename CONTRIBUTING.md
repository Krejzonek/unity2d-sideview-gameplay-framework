# Polski

Dziękuję za zainteresowanie rozwojem projektu!

## Zgłaszanie błędów

Przed utworzeniem zgłoszenia:

1. Sprawdź, czy podobny problem nie został już zgłoszony.
2. Podaj używaną wersję Unity.
3. Opisz kroki pozwalające odtworzyć problem.
4. Dołącz istotne komunikaty z Unity Console.
5. Opisz oczekiwany i rzeczywisty rezultat.

Nie udostępniaj haseł, tokenów, kluczy API ani innych poufnych danych.

## Propozycje zmian

W przypadku większych zmian najpierw utwórz Issue i opisz:

- problem;
- proponowane rozwiązanie;
- wpływ na istniejące systemy;
- ewentualne zmiany zależności.

## Pull Requesty

- Wprowadzaj możliwie niewielkie i konkretne zmiany.
- Nie dodawaj zewnętrznych bibliotek ani zasobów bez sprawdzenia licencji.
- Nie zmieniaj licencji plików należących do innych autorów.
- Sprawdź, czy projekt kompiluje się poprawnie.
- Opisz wprowadzone zmiany i sposób ich przetestowania.

## Styl kodu

Staraj się zachować istniejący styl kodu i unikać niepowiązanych refaktoryzacji.

## Licencja

Wkład powinien być możliwy do udostępnienia na warunkach licencyjnych projektu. Nie przesyłaj kodu ani zasobów, do których nie masz praw.

# English

Thank you for your interest in contributing!

## Reporting Bugs

Before opening an issue:

1. Check whether the problem has already been reported.
2. Include the Unity version you are using.
3. Provide steps to reproduce the issue.
4. Include relevant Unity Console messages.
5. Describe the expected and actual results.

Do not share passwords, tokens, API keys, or other confidential information.

## Suggesting Changes

For larger changes, open an Issue first and describe:

- the problem;
- the proposed solution;
- the impact on existing systems;
- any dependency changes.

## Pull Requests

- Keep changes focused and specific.
- Do not add external libraries or assets without checking their licenses.
- Do not change the license of files owned by other authors.
- Verify that the project compiles correctly.
- Describe your changes and how you tested them.

## Code Style

Try to preserve the existing code style and avoid unrelated refactoring.

## License

Contributions must be suitable for distribution under the project's licensing terms. Do not submit code or assets that you do not have the rights to contribute.
